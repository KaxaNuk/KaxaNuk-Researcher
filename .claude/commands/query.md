# /query

Answer `$ARGUMENTS` from what the owner has actually read, and say where each part came from.

1. **Read the graph first.** Open `Library/INDEX.md` end to end, then follow the links between the
   articles that bear on the question until you have a map of what the library covers. Never answer
   from one article in isolation.
2. **Drill in.** Read the articles the walk surfaced. Quote the source's terms where they matter.
3. **Then the owner's voice.** Read the relevant files in `Notes/` when the owner's own synthesis
   is more specific than the library. Cite them as the owner's view, distinct from the sources'.
4. **Then the raw material,** only if the library is thin: read the source in `Sources/` directly,
   and say the library has no article for it yet.
5. **Answer in chat**, with a standard markdown link to every article and note behind every claim.
   Write to `Output/` only if the owner asks for a file.
6. **Name the gaps.** If the answer needs something the library does not hold, say so and suggest
   the kind of source that would close it. Do not patch the library during a query.

Never read `Notes/Private/` unless the owner names the file in the question. Never invent a source:
if it is not in `Library/`, `Notes/` or `Sources/`, the honest answer is that the library does not
know, followed by what the researcher would read to find out.
